# Стандарт процесса разработки

Этот репозиторий определяет, как разрабатывать продукты и поддерживать их инженерную документацию. Основа процесса — [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills). Здесь находятся расширения требований к артефактам, профили процесса и шаблоны; сами upstream skills не копируются и не переписываются.

Четыре источника составляют правила конкретного продукта:

| Источник | Ответственность |
| --- | --- |
| `addyosmani/agent-skills` | Инженерные практики, выполнение работы и проверка результата |
| `software-development-workflow` | Состав и формат документов, связь артефактов, настройка и развитие процесса |
| Платформа, например `go-product-platform` | Допустимый стек, СУБД, инфраструктура, структура исходников и команды проверки |
| Репозиторий продукта | Выбранный профиль, требования продукта, реальные документы и код |

Все создаваемые документы продукта пишутся **на русском языке в Markdown с YAML frontmatter**. Ключи метаданных, enum, идентификаторы, пути, код и имена API сохраняют техническое написание. Документы хранятся в Git продукта, включая ADR, планы и локальные задачи.

## Подключение

1. Прочитайте [контракт интеграции](docs/integration.md) и выберите [профиль](docs/profiles.md).
2. Зафиксируйте commit этого стандарта, upstream и платформы в продукте по [примеру конфигурации](examples/workflow.yaml). Пример требует заполнения, это не установщик.
3. Добавьте в правила агента [инструкции подключения](examples/product-agents.md). Установите upstream по его документации, проверьте соответствие выбранному SHA.
4. Создайте минимальные документы по [каталогу артефактов](docs/artifacts.md), используя [шаблоны](templates/README.md). Остальные документы создавайте по факту необходимости.
5. Выполняйте [процесс разработки](docs/workflow.md), проверяя документацию вместе с кодом.
