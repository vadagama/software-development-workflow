# Метаданные и жизненный цикл

Каждый авторский Markdown-документ продукта, включая README, AGENTS, HLD, контракты API и событий, описание данных и документы долга, начинается с YAML frontmatter. Исключения: неизменённые сторонние файлы и автоматически сгенерированные документы — их происхождение и исключение фиксируются в конфигурации. Этот стандарт не добавляет поля в upstream SKILL.md. Собственный скилл надстройки [`software-development-workflow-addons`](../skills/software-development-workflow-addons/SKILL.md) кроме полей этой таблицы несёт технические поля формата Agent Skills `name` и `description`; они не заменяют поля контракта.

Метаданные проверяются структурно: frontmatter разбирается безопасно, с отклонением повторяющихся YAML-ключей, и проверяется полученный объект, а не весь Markdown. Правила проверки описаны в [разделе проверки](governance.md). Даты записываются строками в кавычках `YYYY-MM-DD`. Поле `schema_version` версионирует формат метаданных, версия стандарта фиксируется отдельно в конфигурации продукта.

| Поле | Смысл |
| --- | --- |
| `schema_version` | Сейчас `1` |
| `id` | Уникальный ID в пределах продукта; после переноса не меняется |
| `type` | Тип из [каталога артефактов](artifacts.md); собственные расширения требуют изменения стандарта |
| `title` | Русское название |
| `status` | Состояние по таблице ниже |
| `language` | Всегда `ru` для создаваемой документации |
| `owner` | Реальный человек или команда, отвечающие за актуальность |
| `created`, `updated` | Даты создания и последнего содержательного изменения |
| `related` | Массив ID других локальных артефактов; ссылки в тексте ведут к файлам |
| `sources` | Пути от корня продукта и/или URL первоисточников |
| `reality` | Для HLD: `current`, `target` или `mixed` |
| `external_refs` | URL задач внешнего трекера, PR и иных внешних доказательств |
| `extensions` | Объект платформенных метаданных; не переопределяет общие поля |

Допустимые значения `type`: `standard`, `guide`, `readme`, `hld`, `api`, `events`, `data`, `debt`.

| Тип | Состояния |
| --- | --- |
| Все типы | `draft` → `active` → `completed` / `deprecated`; `draft` → `deprecated` |

`active` означает действующий документ, а не автоматически реализованное решение. `completed` используется для завершённых документов, например закрытого долга. Для долга принятие риска описывается в активном документе с владельцем и датой пересмотра; это не закрытие долга. Шаблоны имеют `draft`.

В `reality: mixed` разделы явно помечают текущую и целевую архитектуру. Целевые разделы не доказывают, что решение уже реализовано. Для текущего состояния нужны ссылки на код и проверки; для целевого — задачи upstream-плана и SPEC upstream.
