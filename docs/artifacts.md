# Каталог артефактов продукта

Базовый процесс — upstream skills [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills); этот стандарт — надстройка над ним. Каталог определяет только места и форму продуктовых документов инженерной документации: HLD, контракты синхронных API и асинхронных событий, описание данных и технический долг. Спецификации, планы, задачи, ограничения качества и ADR создаются применимыми upstream skills по их собственным конвенциям и в каталог надстройки не входят.

Структура ниже определяет места хранения, а не требование сразу создать все файлы. Минимум при подключении: README, правила агента и краткий HLD. Контракты появляются с фактической границей или событием, каталог долга — с первым подтверждённым долгом. Для существующего продукта сначала составляется карта текущих документов; перенос выполняется отдельным изменением.

Инициализацию и ведение артефактов в продукте выполняет агент по скиллу [`software-development-workflow-addons`](../skills/software-development-workflow-addons/SKILL.md): создание конфигурации и минимального набора при подключении, сопровождение при изменениях и проверки по [правилам развития и проверки](governance.md). Скилл — процедура для агента, а не установщик; таблицы этого каталога остаются первоисточником требований.

```text
README.md
AGENTS.md
docs/
  hld/README.md                   # весь HLD: контекст, компоненты, развёртывание, NFR
  api/<boundary>.md               # синхронные контракты (REST/RPC/GraphQL)
  events/<event>.md               # асинхронные контракты (события, очереди, потоки)
  data/README.md                  # описание всех данных продукта в одном файле
  debt/DEBT-0001.md               # технический долг
```

| Артефакт / шаблон | Обязательное содержание | Условие создания и обновления |
| --- | --- | --- |
| [HLD](../templates/hld.md) | Контекст, границы, компоненты, потоки, развёртывание, NFR, риски, эксплуатация, безопасность, связанный список ADR | При подключении; изменение системной архитектуры |
| [API](../templates/api.md) | Потребители, авторизация, ошибки, идемпотентность, совместимость | Изменение внешнего или межмодульного интерфейса |
| [События](../templates/events.md) | Производитель, потребители, доставка, порядок, retries, эволюция | Наличие событийного взаимодействия |
| [Данные](../templates/data.md) | Владение, инварианты, consistency, хранение, миграция, удаление | Долговечные данные и изменение их модели |
| [Долг](../templates/debt.md) | Доказательство проблемы, последствия, риск, варианты, проверка закрытия | Подтверждённый долг; гипотеза сначала проверяется |

HLD хранится целиком в `docs/hld/README.md`: контекст, компоненты, развёртывание, NFR, эксплуатация и безопасность — разделы одного файла. Детальное устройство модуля описывает его спецификация, которую ведёт upstream skill; отдельные LLD не создаются. Значимые архитектурные решения фиксируются по конвенции upstream `documentation-and-adrs` в каталоге, выбранном продуктом; надстройка не резервирует для них отдельный путь. HLD связан с этим списком решений: в разделе решений HLD ведётся перечень принятых ADR со ссылками на записи каталога решений, дополненный при появлении нового ADR или изменении влияющего на архитектуру решения.

Синхронные интерфейсы описываются в `docs/api/<boundary>.md`, асинхронные — в `docs/events/<event>.md`. Контракты в Markdown описывают смысл и ссылаются на машинный первоисточник: OpenAPI, AsyncAPI, Protobuf, GraphQL, миграции, схемы событий или иной формат платформы. Их нельзя вручную дублировать целиком. Все данные продукта описываются в одном файле `docs/data/README.md`, разделённом на домены. Требование Markdown + frontmatter относится к документации, а не к исходникам, SQL, схемам контрактов и конфигурации.

Спецификации, планы, списки задач, ограничения качества (CONSTRAINTS), ADR и CHANGELOG не входят в каталог надстройки: их создаёт и ведёт применимый upstream skill — `spec-driven-development`, `planning-and-task-breakdown`, `constraint-driven-development`, `documentation-and-adrs`, `shipping-and-launch` — в своих конвенциях (`spec/`, `tasks/plan.md`, `tasks/todo.md`, `CONSTRAINTS.md`, каталог решений). Содержание этих документов в продукте также пишется на русском и хранится в Git.

## Что переиспользовано из upstream

Форму спецификаций, планов, задач, CONSTRAINTS и ADR этот стандарт не дублирует: она определена в соответствующих upstream skills. Оценка влияния и результаты проверок записываются в разделах плана и задач upstream; отдельных файлов `spec/impact/`, `spec/verification/`, `operations/` и `security/` нет — эксплуатация и безопасность включаются в HLD и проверки задач.

HLD, контракты API и событий, данные, долг и метаданные — обязанности этой надстройки; их сопровождает собственный скилл надстройки [`software-development-workflow-addons`](../skills/software-development-workflow-addons/SKILL.md), не дублирующий upstream skills.

Все документы продукта, включая текст, таблицы и подписи схем, пишутся на русском. Названия технологий, код, API-идентификаторы, YAML-ключи и значения перечислений сохраняют техническое написание.
