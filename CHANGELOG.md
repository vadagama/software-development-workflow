# История изменений

### Скилл артефактов надстройки — 2026-11-23

- Добавлен скилл `software-development-workflow-addons` (`skills/software-development-workflow-addons/SKILL.md`): инициализация `.workflow/config.yaml` и минимального набора артефактов надстройки в новом продукте, подключение существующего, ведение при изменениях и проверка по governance. Скилл — процедура агента, а не установщик; требования каталога не изменялись.
- README, каталог артефактов, интеграция, карта upstream, метаданные, шаблоны и пример правил агента ссылаются на скилл как на способ исполнения требований.
- `SKILL.md` несёт поля формата Agent Skills (`name`, `description`) рядом с полями контракта метаданных; контракт `STD-METADATA` дополнен пояснением.

### Связь HLD со списком ADR — 2026-11-23

- HLD обязан поддерживать связанный список принятых ADR: записи формируются по конвенции upstream `documentation-and-adrs`, ссылки на них ведутся в разделе решений HLD.
- Требование внесено в каталог артефактов, шаблон и пример HLD, карту upstream и этапы проектирования; содержательная проверка сверяет список ADR в HLD с фактическим каталогом решений.

### Слияние документов надстройки — 2026-11-23

- Документы надстройки сокращены с восьми до пяти без изменения требований: `profiles.md` объединён с контрактом интеграции, `workflow.md` — с картой upstream, `evolution.md` и `validation.md` — в новом `docs/governance.md` (`STD-GOVERNANCE`).
- Карта upstream сжата: полный перечень 26 навыков заменён таблицей этапов, дополнениями надстройки и списком навыков, действующих в оригинале.
- Согласованно обновлены README, правила сопровождения, метаданные, шаблоны и пример подключения агента; ID `STD-PROFILES`, `STD-WORKFLOW`, `STD-EVOLUTION` и `STD-VALIDATION` выведены из употребления.

### Сокращение каталога надстройки — 2026-11-23

- Артефакты надстройки: HLD в `docs/hld/README.md`, синхронные контракты в `docs/api/<boundary>.md`, события в `docs/events/<event>.md`, все данные в одном `docs/data/README.md`, долг в `docs/debt/DEBT-NNNN.md`.
- SPEC, планы, задачи, CONSTRAINTS, ADR и CHANGELOG выведены в конвенции upstream skills; надстройка их не каталогизирует и не дублирует.
- Удалены шаблоны CONSTRAINTS, ADR, capability-map, SPEC, план, задачи, инициативы и README продукта; убран учебный пример инициативы.
- `.workflow/config.yaml` убран из дерева артефактов; конфигурация подключения описывается только контрактом интеграции.
- Добавлен учебный пример синхронного контракта API (`examples/api/booking.md`) со связью с HLD.
- Данные продукта описываются одним файлом `docs/data/README.md` по разделам доменов.
- Согласованно обновлены метаданные, профили, процесс, интеграция, карта upstream, проверка, шаблоны и примеры.

## 0.1.0 — 2026-11-21 (проект редакции, тег не опубликован)

- Определены границы upstream, стандарта, платформы и продукта.
- Добавлены русскоязычные артефакты Markdown + YAML frontmatter, каталог и шаблоны.
- Описаны профили, подключение, проверка, обновление upstream и миграция документов.
- Сохранены upstream-пути `spec/`, `tasks/plan.md`, `tasks/todo.md`; патчи skills не используются.

### Уточнение структуры — 2026-11-21

- По запросу пользователя HLD объединён в один файл, каталог ADR сделан плоским.
- Убраны отдельные артефакты влияния, проверки, эксплуатации и безопасности; необходимое содержание перенесено в план, задачи и HLD/LLD.
- Пути карты возможностей и модульных SPEC сверены с закреплённым upstream.
- Добавлены учебные русскоязычные примеры со схемами и ссылками на публичные первоисточники.
- Разделены имена индекса шаблонов и шаблона README для файловых систем без учёта регистра.
- Убрана JSON Schema метаданных: требования к frontmatter, полям и допустимым значениям описаны в [метаданных](docs/metadata.md) и проверяются структурной проверкой.

### Удаление LLD — 2026-11-21

- Артефакт LLD убран из каталога, метаданных, профилей, процесса и примеров: детальное устройство модуля дублировало SPEC.
- Ответственность, интерфейсы, состояния, алгоритмы и обработка ошибок модуля описываются в SPEC этого модуля; HLD остаётся системным описанием.
- Поле `level` у ADR удалено вместе с уровнями `hld` и `lld`; ADR ведутся одной последовательностью в `docs/architecture/decisions/`.
- Переход для продуктов: алгоритмические разделы существующих LLD перенести в SPEC соответствующих модулей, поле `level` из ADR убрать, каталог `docs/architecture/lld/` свернуть отдельным изменением с проверкой обратных ссылок.

### Удаление примера ADR — 2026-11-21

- Учебный пример ADR убран: процесс и форма решений уже определены в upstream skill `documentation-and-adrs`, а вымышленный сценарий бронирования не имеет отношения к upstream.
- Тип `adr`, шаблон `templates/adr.md` и правила жизненного цикла сохранены как контракт формата продукта; пути ADR и правило фиксации значимых решений не менялись.
- Связи примеров с удалённым документом сняты (HLD, данные, долг, инициатива); продуктовые ADR миграции не требуют.
